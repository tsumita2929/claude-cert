## 本文

### 直前チェック10

最後に、試験の直前に聞き直してほしい、10のチェックポイントです。

一つ。エージェントループは、`stop_reason` で回します。`tool_use` なら続け、`end_turn` なら終えます。「完了」の言葉や文章の有無で止めず、回数の上限は安全網にします。

二つ。必ず守らせたい規則は、プロンプトではなく仕組みで強制します。前提条件ゲートで、本人確認が済むまで返金を止めます。`PreToolUse` フックで方針違反を止め、`PostToolUse` フックで結果の形式をそろえます。

三つ。サブエージェントは、会話履歴を引き継ぎません。必要な情報は、本文と出典を分けた構造化データで、丸ごと渡します。レポートの抜けは、まずコーディネーターの分解を疑います。

四つ。ツールの説明が、選択の決め手です。似たツールは、説明と名前で分けます。各サブエージェントには、役割に必要なツールだけを渡します。

五つ。エラーは、`isError` に、種類とリトライの可否を付けて返します。該当なしという空の結果と、アクセスの失敗は区別します。

六つ。チームの規約は、プロジェクトの CLAUDE.md に書きます。ユーザーレベルは自分だけです。散らばったファイルには、`paths` を付けたルールを使います。

七つ。複雑さが見えている作業は、プランモードから始めます。CI では `-p` を付け、`--output-format json` と `--json-schema` で結果を受け取ります。

八つ。「保守的に」ではなく、報告する条件を具体的に書きます。形式がそろわなければ、few-shot の例を見せます。レビューは、独立したインスタンスに任せます。

九つ。`tool_use` と JSON スキーマで形を強制し、意味の誤りは別に検証します。文書にない情報はリトライで直らないので、`null` を許します。バッチは50%安く最大24時間なので、待てる処理だけに使います。

そして十。取引の事実は、「ケースの事実情報」ブロックで毎回渡します。人を求められたら、すぐに引き継ぎます。食い違う値は、出典付きで両方を残します。

**要点**
- `stop_reason` で回す。上限は安全網
- 必ず守らせることは、ゲートとフックで強制
- サブエージェントには文脈を丸ごと構造化して渡す
- ツールの説明が選択の決め手。ツールは役割に必要な分だけ
- エラーは種類とリトライ可否を付け、空の結果と区別
- チームの規約はプロジェクトの CLAUDE.md、散らばるなら `paths`
- 複雑ならプランモード。CI は `-p` と JSON 出力
- 報告条件は具体的に。レビューは独立したインスタンス
- スキーマで形を、検証で意味を。ない情報は `null` 可
- 事実はブロックで保持。人の要求はすぐ引き継ぐ
