# 第2章 マルチエージェントの設計

- 試験: CCAR-F ／ 分野1 エージェントアーキテクチャとオーケストレーション（27%）／ タスク 1.2、1.3、1.6、1.7
- 確認日: 2026-11-16

## 本文

### この章で学ぶこと

第2章は、分野1の、エージェントアーキテクチャとオーケストレーションのうち、複数のエージェントを組み合わせる部分です。分野1は配点が27%で、5つの分野で最大です。範囲は、タスクステートメントの1.2、1.3、1.6、1.7です。仕事の分け方、任せ方、引き継ぎ方の判断を学びます。

**要点**
- 分野1の後半。タスクは1.2、1.3、1.6、1.7
- 複数のエージェントを組み合わせる設計を扱う
- 仕事の分け方、任せ方、引き継ぎ方を判断する

### コーディネーターが、すべての通信を仲介する

マルチエージェントの基本の形が、コーディネーターとサブエージェントです。中心のコーディネーターが、タスクを分解し、サブエージェントに任せ、結果をまとめます。この形を、ハブアンドスポーク型アーキテクチャと呼びます。

サブエージェントどうしは、直接やり取りしません。通信も、エラーの処理も、情報の振り分けも、すべてコーディネーターを通します。そうすれば、何が起きたかを1か所で観察でき、エラーを同じ方針で扱え、情報の流れを制御できます。エラーの伝え方は、第8章で扱います。

また、コーディネーターは、問い合わせの要件を見て、呼ぶサブエージェントを、その都度動的に選びます。

**要点**
- コーディネーターが分解、委任、集約を受け持つ
- サブエージェントどうしは直接やり取りしない
- 通信を集めると、観察、エラー処理、情報の制御がしやすい
- 呼ぶサブエージェントは、問い合わせに応じて選ぶ

### 抜けの原因は、コーディネーターの分解にある

気をつけたいのが、分解が狭すぎるリスクです。幅広いテーマのレポートが、一部の分野しか扱っていないとします。各サブエージェントは、割り当てどおりに正しく動いています。このとき原因は、下流ではなく、テーマを狭く分けすぎた上流のコーディネーターです。

範囲は、サブトピックや情報源の種類ごとに分けて割り当てると、重複が減ります。さらに、コーディネーターが統合の結果を評価し、抜けがあれば、的を絞った問い合わせで、検索や分析をもう一度任せます。カバーが十分になるまで、統合をやり直します。これが、反復的な改善ループです。

**要点**
- レポートの抜けは、まずコーディネーターの分解を疑う
- サブトピックや情報源の種類で分けると、重複が減る
- 統合の結果を評価し、抜けに絞って再委任する

### サブエージェントには、必要な文脈をすべてプロンプトで渡す

サブエージェントは、分離されたコンテキストで動きます。コーディネーターの会話履歴を自動では引き継がず、呼び出しをまたいでメモリも共有しません。必要な情報は、呼び出すときのプロンプトに明示して渡します。

Agent SDK で、サブエージェントを起動する仕組みが、`Task` ツールです。コーディネーターが使うには、`allowedTools` に `Task` を含めます。種類ごとの設定は、`AgentDefinition` に書きます。中身は、いつ使うかの説明、システムプロンプト、ツールの制限です。

渡し方の決まりは2つです。まず、前のエージェントの調査結果を、丸ごとプロンプトに入れます。次に、本文とメタデータを分けた、構造化データにします。メタデータとは、出典の URL や文書名、ページ番号です。分けておけば、どの主張がどの出典からかが、最後まで残ります。

なお、2026年11月時点のドキュメントでは、`Task` ツールは `Agent` ツールに名前が変わり、古い名前も設定で使えます。会話を丸ごと写す、フォークというサブエージェントも加わりました。試験では、ガイドのとおりに考えてください。

**要点**
- サブエージェントは、親の会話履歴を引き継がない
- 起動は `Task` ツール。`allowedTools` に `Task` を含める
- `AgentDefinition` に、説明、システムプロンプト、ツールの制限
- 前の調査結果は丸ごと、出典は本文と分けて渡す

### 並列に起動し、手順ではなく目標で任せる

独立した調査は、並列に起動します。コーディネーターの1回の応答で、複数の `Task` 呼び出しを出します。ターンを分けて1つずつ呼ぶと、時間は全部の合計です。並列なら、いちばん遅い1つの時間で済みます。

コーディネーターの指示には、手順を並べず、調査の目標と品質の基準を書きます。手順を固定すると、サブエージェントが、途中で見つけたことに合わせて動けないからです。

**要点**
- 独立した仕事は、1回の応答で複数の `Task` を出す
- 並列なら、いちばん遅い1つの時間で終わる
- 指示は手順ではなく、目標と品質の基準

### 決まった手順はプロンプトチェーン、先が読めない調査は動的に分解する

タスクの分解には、2つの型があります。

1つ目は、プロンプトチェーンです。決まった順番のステップに分け、前の出力を次の入力にします。予測できる作業に向き、典型は大きなコードレビューです。まずファイルごとに分析するパスを回し、次に、ファイルをまたぐ問題を見る統合のパスを、別に回します。一度に全部見せると、注意が分散して見落としが出ます。

2つ目は、動的な分解です。各ステップで分かったことから、次のサブタスクを作ります。終わりの見えない調査に向いています。レガシーなコードベースに網羅的なテストを足すなら、まず構造を把握し、影響の大きい領域を見つけ、優先順位を付けた計画を作ります。依存関係が見つかるたびに、計画を組み替えます。

**要点**
- 予測できる多観点のレビューは、プロンプトチェーン
- 大きなレビューは、ファイルごとのパスと横断のパスに分ける
- 終わりの見えない調査は、分かったことに応じて分解する

### 再開するか、要約を持って新しく始めるか

最後は、セッションの管理です。セッションとは、エージェントとのやり取りの履歴です。Claude Code では、`--resume` にセッション名を付けて、名前付きの会話を再開できます。作業日をまたぐ調査に便利です。

共通の分析から別のアプローチを試すなら、`fork_session` で分岐を作ります。元のセッションは残るので、たとえば2つのテスト戦略を比べられます。

再開では、ツールの結果が古くないかに気をつけます。セッションが保存するのは会話で、ファイルではありません。コードを変えたなら、変えたファイルを具体的に伝え、そこだけを分析し直させます。前の結果の多くが古いなら、再開はしません。大事な事実をまとめた構造化された要約を渡して、新しいセッションを始めます。

**要点**
- `--resume` とセッション名で、名前付きの会話を再開する
- `fork_session` で、共通の分析から独立した分岐を作る
- 再開したら、変えたファイルを具体的に伝える
- 古い結果が多いなら、要約を持って新しく始める

### ミニクイズ

それでは、ミニクイズです。

リサーチシステムで、統合役のレポートに出典が載らなくなりました。コーディネーターは、検索役の結果を短く要約して、統合役に渡しています。最も適切な対応はどれでしょうか。1番、統合役のシステムプロンプトで、出典を必ず書くよう強く指示する。2番、検索役の結果を、本文と出典の情報を分けた構造化データにして、丸ごと渡す。3番、統合役が、検索役の会話履歴を直接読めるように設定する。

@pause 4

正解は、2番です。統合役は渡されたものしか知らないので、出典が届かなければ書けません。3番は、文脈を引き継がない仕組みにも、通信をコーディネーターに集める原則にも反します。

### 試験ガイドと現行ドキュメントの食い違い

- 食い違い1（ツールの名前）: 試験ガイドは、サブエージェントを起動するツールを `Task` と呼び、`allowedTools` に `"Task"` を含めるとする。2026年11月時点のドキュメントでは、Claude Code v2.1.63 で `Agent` に改名され、Agent SDK の例も `allowedTools` に `"Agent"` を書く。`Task(...)` という古い書き方は、設定とエージェント定義では別名として使える（`system:init` のツール一覧では今も `"Task"` と出る）。本文はガイドの `Task` を主にし、改名を一言添えた。問題集では、正解の選択肢を `Task` で書き、`Agent` を「存在しない名前」として誤答に使わないこと。
- 食い違い2（フォーク）: 試験ガイドは「サブエージェントは親の文脈を自動では引き継がない」とする。2026年11月時点の Claude Code と Agent SDK には、会話を丸ごと引き継ぐフォークのサブエージェント（`subagent_type: "fork"`、`/subtask`）がある。フォーク以外のサブエージェントは今も引き継がない。本文はガイドの原則を主にし、フォークの存在を一言添えた。
- 参考（本文には入れていない）: 現行のドキュメントでは、サブエージェントが自分のサブエージェントを起動できる（既定で3層まで）。ガイドのハブアンドスポークの説明と直接は矛盾しないが、問題集で「サブエージェントは決して起動できない」と言い切る選択肢は避けること。
- 参考: `fork_session` は Agent SDK の Python のオプション名（TypeScript では `forkSession`、Claude Code の CLI では `--fork-session`）。ガイドの表記どおり `fork_session` で書いた。
