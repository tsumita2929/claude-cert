## 試験ガイドと現行ドキュメントの食い違い（素材と同じ扱い）

- **確信度によるふるい分け。** ガイド（タスク 4.1）は「確信度に基づくフィルタリングに頼らず、カテゴリ別の具体的な基準を書く」。2026年11月時点のドキュメント（Prompting Claude Opus 4.8 の Code review harnesses）は、指摘の段階ではすべてを確信度と重大度つきで出させ、別の段階でふるい分ける構成を勧める（単一パスなら報告の線を具体的に書く）。台本はガイドの立場を主にし（場面 criteria、report の前半）、現行の助言を report の後半で一言添えた。あいまいな指示を避けて具体的な線を書く点は両者で一致する。
- **few-shot の例の数。** ガイドは「あいまいな場面に絞った2〜4個」、現行の Prompting best practices は一般的な目安として「3〜5個」。台本は2〜4個をガイドの目安として言い、3〜5個を現行の一般的な目安として添えた（画面の補足にも出す）。
- **拡張思考。** ガイドの言い方「拡張思考」のままにした。現行では `budget_tokens` による従来の extended thinking は legacy の扱いで、adaptive thinking と `effort` が中心だが、台本では仕様の細部に触れていない。

## 素材から変えた点、省いた点

- **画面のコード例（`<example>` の見本）は、説明用の自作。** 場所・問題・重大度・修正案・理由の5項目の形を見せるためのもので、ファイル名や行番号は架空。中身（SQL への文字列の連結をセキュリティの問題として扱う）は一般的な例で、台本のナレーションでは主張していない。
- **省いた内容（長さの都合）。** 方法論が独立した節にある文書と本文に埋め込まれた文書の例、くだけた書き方の分量の扱い（素材 #14 の一部）。Claude Code の公式ドキュメントの「会話を見ていない新しいサブエージェントのレビューは、推論に引きずられない」（素材 #17）。
- **「ときどきしか見つからない」を「まれにしか出ない」と言い換えた。** 字幕の長さの都合。
- **ミニクイズは3択から4択にした。** 選択肢 D（3回レビューして一致した指摘だけ残す）は、素材のマルチパスの節（#19）の内容から作った誤答。正解の番号は「2番」から「B」になった。
- 読みの都合で、「空や null」を「空欄や null」に、クイズの解説の「止めれば」を「無効にすれば」に変えた（音声エンジンが「ソラ」「ヤメレバ」と読むため）。

## 未確認のまま残っている主張

なし（素材の「確認できなかった点」も「なし」。独立したレビューインスタンスが拡張思考より効果的という比較、マルチパスの分け方、誤検知カテゴリの一時停止は、試験ガイドの記載が根拠。現行ドキュメントに同じ比較の記述はないが、反する記述もない）。
