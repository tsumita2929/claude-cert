# 講座の章の書き方

各試験フォルダの `course/chNN.md` が、その章の「正」になる本文です。音声講座（`audio/script.txt`）、スライド、解説動画は、どれもこのファイルを素材にして作ります。だから、ここでの事実確認が全部の教材の品質を決めます。

```
course/chNN.md ──(shared/audio/make_script.py)──▶ audio/script.txt ──▶ 音声（m4a）
               ──▶ slides/build_deck.js（スライド）
               ──▶ video/episodes/epNN-*/episode.json（解説動画）
```

章の範囲と題名は、その試験の `reference/outline.md` で決めてあります。題名は変えません（動画の「次回」の予告と対応しているため）。

## 1. 何を書くか

- **範囲は試験ガイドが決める。** `reference/outline.md` にある、その章の分野・タスクだけを扱う。公式の試験ガイド（`reference/*_exam_guide_v1.0_ja.txt` と `_en.txt`）の該当部分を必ず読み、ガイドが挙げる知識・スキルを落とさない。ガイドにない話題を広げない。ほかの章の範囲には踏み込まない（一言触れて「第N章で扱います」と送る）。
- **用語は公式の日本語版ガイドに合わせる。** 日本語で受験する人は、その訳語を試験で目にする（例: domain は「分野」、plan mode は「プランモード」）。
- **判断の軸を教える。** 試験は「この状況で最も適切な対応はどれか」を問う。機能の説明で終わらせず、「なぜそれを選ぶのか」「もっともらしいが劣る選択肢は何か、なぜ劣るのか」まで書く。`reference/blueprint.md` の「問題の傾向」に、公式サンプル問題から読み取った誤答の型がある。
- **出題の傾向を言い切らない。** 実際の試験の中身は、こちらには分からない。「よく問われる」「試験でねらわれる」とは書かず、「間違えやすいのは」「気をつけたいのは」のように書く。公式サンプル問題に触れるときは、出どころ（試験ガイドのサンプル問題）を言い、問題文と選択肢は写さない。
- **分量は、音声で5〜7分。** 「## 本文」の地の文が 1,800〜2,300字（要点の箇条書きは数えない）。節は4〜7個。
- **最後にミニクイズを1問。** 自作する。公式サンプル問題や、ほかの対策サイトの問題を写さない・言い換えない。

## 2. 事実確認（いちばん大事）

資格の解説は、1か所の誤りで教材全体の信用を失います。本文に書く主張は、**書く前に**一次情報で確かめます。

- **一次情報だけを根拠にする。** 公式の試験ガイド、Anthropic の公式ドキュメント、公式のヘルプセンター、公式のエンジニアリング記事。対策サイトやブログは根拠にしない。
  - API・エージェント・ツール: https://platform.claude.com/docs/ （ページの URL の末尾に `.md` を付けると Markdown で取れることが多い。`https://platform.claude.com/llms.txt` にページの一覧がある）
  - Claude Code と Agent SDK: https://code.claude.com/docs/ （同じく `https://code.claude.com/docs/llms.txt`）
  - MCP: https://modelcontextprotocol.io/
  - Claude のアプリ（Projects、Artifacts、Research、Memory、Skills、コネクタ）: https://support.claude.com/ （ヘルプセンター）と https://claude.com/
  - 設計の考え方: https://www.anthropic.com/engineering/ の記事（Building effective agents、Effective context engineering for AI agents、Writing effective tools for agents、How we built our multi-agent research system など）
  - 利用上の決まりとデータの扱い: https://www.anthropic.com/legal/aup 、https://privacy.claude.com/ 、https://trust.anthropic.com/
  - Skill ツールで `claude-api` を読み込むと、現行の API リファレンスのまとめが読める。
- **自分の記憶で書かない。** あなたの知識より新しい仕様変更がある（モデルの系統、パラメータの廃止、機能の名前の変更など）。数値、名前（パラメータ、コマンド、ファイルの置き場所）、「必ず」「〜だけ」という言い切りは、特に確かめる。
- **試験ガイドと、現行のドキュメントが食い違うとき。** 試験ガイドは発効時点（v1.0 は2026年7月。CCAR-F の中身は2026年3月から同じ）の製品を前提に書かれている。その後に製品が変わっていることがある。
  - 試験は試験ガイドに沿って出る。本文は**ガイドの立場を主**にして書く。
  - 現行の仕様が違う場合は、「試験ガイドではこう扱う。2026年11月時点のドキュメントではこう変わっている」と短く添える。受験者が実務で困らないようにするため。
  - 食い違いは、ファイルの「事実確認」の節に必ず書く（スライド・動画・問題集の担当が同じ判断をできるように）。
- **確認できなかった主張は、本文から外す。** どうしても必要なら「〜とされています」と弱め、「確認できなかった点」に書く。
- **変わりやすい情報は言い切らない。** モデルの版の番号、料金の金額、上限の数値は、原則として本文に入れない。入れるときは「2026年11月時点」と添える。
- **試験の形式や配点の数字**は、`reference/outline.md` の値をそのまま使う（公式ガイドで確認済み）。

## 3. 文章の決まり

本文は、そのまま音声で読み上げられます。耳で聞いて分かる文章にします。

- **です・ます体。1文は短く、1文に1つのこと。** 主語と述語を近づける。かっこ書きに頼らない（かっこの中は読み上げで不自然になる）。
- **節の見出しは、覚えてほしい結論を言い切る。** 「stop_reason について」ではなく「stop_reason を先に確認する」。見出しは音声では読まれないので、本文は見出しがなくても通じるように書く（節の最初の文で話題を言う）。
- **記号に頼らない。** 「→」「／」「＝」「〜」や箇条書きは、地の文では使わない。「AからBへ」「AまたはB」のように言葉で書く。箇条書きにしたい内容は「要点」に書く。
- **英語の用語は原綴りのまま書く。** `max_tokens`、Claude Code、MCP のように。コード上の名前（パラメータ、コマンド、ファイル名、ツール名）だけをバッククォートで囲む。ふつうの英単語や製品名は囲まない。読み方は「## 読み」の表に書く（音声用に自動で置き換わる）。
- **数字は算用数字。** 「3つ」「80%」「120分」。HTTP のステータスコードのように1桁ずつ読ませたい数字は、「## 読み」の表に読みを書く（例: `429` → ヨンニーキュー）。
- **むずかしい言葉を言い換える。** 初めて出る用語は、その場で一言で説明する。
- 既存の講座（`CCDV-F/audio/script.txt`。こちらは読みのカタカナに変換済みの形）が、語り口と密度の手本になる。

## 4. ファイルの書式

`course/chNN.md`（NN は章番号の2桁）を、次の形で書きます。見出しの名前（「本文」「読み」「事実確認」）は変えないでください。ツールがこの名前で読み取ります。

````markdown
# 第3章 ツール設計と MCP 統合

- 試験: CCAR-F ／ 分野2 ツール設計と MCP 統合（18%）／ タスク 2.1〜2.5
- 確認日: 2026-11-16

## 本文

### （冒頭の節。見出しは「この章で学ぶこと」のような短いものでよい）

第3章は、分野2の、ツール設計と MCP 統合です。配点は18%です。……（この章で何が分かるようになるかを2〜3文で）

### ツールの説明文が、ツール選択の精度を決める

Claude は、ツールの説明文を読んで、どのツールを使うかを決めます。……

（2〜5段落。空行で段落を分ける）

**要点**
- ツールの説明文は、モデルが読むプロンプトの一部
- 入力の形式、例、境界（いつ使う・使わない）を書く
- 似たツールは、名前と説明で違いをはっきりさせる

### （次の節）

……

### ミニクイズ

それでは、ミニクイズです。

（状況と問いを、耳で聞いて分かる長さで。選択肢を出すなら「1番、〜。2番、〜。3番、〜。」と文章で）

@pause 4

正解は、〜です。（理由を1〜2文で）

## 読み

| 表記 | 読み |
|---|---|
| `isError` | イズ・エラー |
| `.mcp.json` | ドット・エムシーピー・ドット・ジェイソン |
| stdio | スタンダード・アイオー |

## 事実確認

| # | 本文の主張 | 判定 | 根拠（URL と、該当箇所の要旨） |
|---|---|---|---|
| 1 | ツールの説明文は、ツール選択の主な手がかりになる | 正しい | 試験ガイド タスク 2.1「…」／ https://platform.claude.com/docs/…「…」 |

### 試験ガイドと現行ドキュメントの食い違い

- （なければ「なし」。あれば、ガイドの記載、現行の記載、本文でどう書いたか）

### 確認できなかった点

- （なければ「なし」）
````

書式の細かい決まり:

- **「要点」は各節に3〜5個。** スライドと動画の画面にそのまま出る。短く言い切る（1個 40字まで）。地の文と同じ内容でよいが、地の文にない新しい事実を要点だけに書かない。
- **「## 読み」の表には、その章の本文に出る英字の語をすべて載せる。** `shared/audio/lexicon.json` にある基本の語（Claude、API、MCP、JSON など）は載せなくてよい。読みはカタカナで、語の切れ目に「・」を入れる。
- **`@pause 4` は、ミニクイズの問いのあとに1回だけ。** 行の前後を空行にする。
- 「## 本文」の中に、表や引用（`>`）や番号付きの箇条書きを地の文として書かない（読み上げから外れる）。
- ミニクイズの節の見出しは「### ミニクイズ」にする。

## 5. 書き終えたら確かめる

```bash
# リポジトリの直下で実行する
python3 shared/audio/make_script.py <試験> --stdout --only ch03    # 自分の章（例: ch03.md）が、読み上げの文としてどう出るか
```

- 自分の章の部分に、**英字が残っていないか**を見る。残っていたら「## 読み」に足す。
- 見出しを飛ばして読んでも、話がつながるか。
- 字数（地の文で 1,800〜2,300字）。次のように数えられる:
  `python3 shared/audio/make_script.py <試験> --stdout --only ch03 | grep -v -e '^# ' -e '^@pause' | tr -d '\n' | wc -m`
- `--only` を付ければ、ほかの章が書きかけでも影響を受けない。**ほかの担当のファイルは書き換えない。**
