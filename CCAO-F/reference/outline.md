# CCAO-F 教材の設計（章立てと問題の配分）

Claude Certified Associate – Foundations（試験コード CCAO-F）の非公式教材の設計です。講座（音声・スライド・動画）の章立てと、問題集の配分をここで決めています。出題範囲の詳しい調査は `blueprint.md`、公式の試験ガイドは同じフォルダの PDF とテキストにあります。

## 試験の基本情報（公式試験ガイド v1.0、2026年7月発効。2026-11-16 に確認）

| 項目 | 内容 |
|---|---|
| 問題数・時間 | 60問・120分（受付などを含めた着席時間は約135分） |
| 合格点 | 100〜1,000 のスケールスコアで 720。換算式は非公開（「72%正解」という意味ではない） |
| 出題形式 | 択一式と複数選択式（選ぶ数は問題に書いてある）。業務の場面を示して、最も適切な行動を選ばせる |
| 受験 | Pearson VUE。オンライン監督（OnVUE）かテストセンター。クローズドブック。英語と日本語で受験できる |
| 受験資格 | Claude Partner Network に加盟している組織の人（会社のメールアドレスで申し込む）。前提資格はなし |
| 料金・有効期間 | 99 USD（パートナーの割引前）・12か月 |
| 対象者 | Claude を日々の仕事の道具として使い、Claude のプロジェクト機能でプロジェクトを作る実務者（オペレーション、マーケティング、プロジェクト管理、教育、広報、コンサルタントなど）。プログラミングや API の経験は不要 |
| **今後の変更** | **2026-12-07 に試験内容が更新される。** 更新版の試験ガイドは 2026-11-17 に公開され、このフォルダに保存してある（`CCAO-F_exam_guide_v1.1-2026-12-07_*`）。70問（採点対象60＋対象外10）、6分野（15／20／15／18／15／17%）に変わり、スキルも再編される。**この教材は、改訂前（12月6日までの試験）のガイドに基づいたまま**（2026-11-18 時点の方針）。差分のまとめは `shared/program.md` の冒頭の追記。12月7日以降に受ける人は、新しいガイドとの差分を確かめること |

分野（公式の日本語版ガイドは domain を「分野」と訳す）と配点。タスクは全部で30（公式のガイドに番号はない。下の「1.1」などは、この教材で便宜上付けた番号で、`blueprint.md` と同じ）:

| 分野 | 名称 | 配点 | タスク |
|---|---|---|---|
| 分野1 | プロンプト作成とタスク実行（Prompting and Task Execution） | 14% | 1.1〜1.4 |
| 分野2 | 出力の評価と検証（Output Evaluation and Validation） | 21% | 2.1〜2.6 |
| 分野3 | 製品とモデルの選択（Product and Model Selection） | 12% | 3.1〜3.4 |
| 分野4 | ワークフロー統合とソリューション設計（Workflow Integration and Solution Design） | 16% | 4.1〜4.5 |
| 分野5 | 設定とナレッジ管理（Configuration and Knowledge Management） | 12% | 5.1〜5.4 |
| 分野6 | ガバナンス、リスク、責任ある利用（Governance, Risk, and Responsible Use） | 15% | 6.1〜6.4 |
| 分野7 | トラブルシューティングと最適化（Troubleshooting and Optimization） | 10% | 7.1〜7.3 |

この試験の色合い: 技術者向けではない。**製品仕様の暗記ではなく、仕事での判断**（確かめてから出す、タスクに合わせて選ぶ、規制対象のデータを守る、手に負えないものは技術担当に渡す）を問う。公式のガイドが名前を挙げている製品・機能は、Projects（プロジェクト）、Artifacts（アーティファクト）、リサーチ（research mode）、チャット、モデルの種類（Haiku、Sonnet、Opus）、コンテキストの制限とメモリ、Memory、Skills、Code Execution、コネクタ（Google Drive、Gmail など）、システムレベルの指示とナレッジソース。**ガイドに出てこないもの**（料金プランの違い、管理コンソール、Cowork、Claude in Chrome、API、Claude Code、MCP、特定の法律の名前）を、正解の根拠にしない。公式の対策講座（Partner Academy の Prep Course、8モジュール）の学習目標が `blueprint.md` の4章にある（公式だが試験ガイドではない）。対策講座は Anthropic の「AI Fluency」の枠組み（4つの D: Delegation 委任、Description 記述、Discernment 見極め、Diligence 責任ある実践）を使っている。

対象の読者はエンジニアではない。講座も問題も、**専門用語を使わずに、職場の場面で**書く（営業資料、議事録、顧客への返信、規程の要約、採用、研修資料など）。

## 講座の章立て（全8章。音声の章、スライドの章、動画の回が1対1で対応する）

シリーズ名は「CCAO-F キャッチアップ講座」。音声講座は、この8章の前に「オープニング」「試験の全体像」、後ろに「総復習 直前チェック10」が付く（`course/ch00a.md`、`ch00b.md`、`ch99.md`）。

| 章 | 題名（変えない） | ファイル | 動画のフォルダ名 | 範囲 |
|---|---|---|---|---|
| 1 | 伝わるプロンプトの作り方 | `course/ch01.md` | `ep01-prompting` | 分野1 のタスク 1.1〜1.4 |
| 2 | 出力を確かめる | `course/ch02.md` | `ep02-evaluating-output` | 分野2 のタスク 2.1、2.2、2.3 |
| 3 | 人の確認と仕上げ | `course/ch03.md` | `ep03-review-and-refine` | 分野2 のタスク 2.4、2.5、2.6 |
| 4 | 製品とモデルの選び方 | `course/ch04.md` | `ep04-product-and-model` | 分野3 のタスク 3.1〜3.4 |
| 5 | 業務への組み込み | `course/ch05.md` | `ep05-workflow-integration` | 分野4 のタスク 4.1〜4.5 |
| 6 | 設定とナレッジ管理 | `course/ch06.md` | `ep06-configuration` | 分野5 のタスク 5.1〜5.4 |
| 7 | ガバナンスと責任ある利用 | `course/ch07.md` | `ep07-governance` | 分野6 のタスク 6.1〜6.4 |
| 8 | うまくいかないときの直し方 | `course/ch08.md` | `ep08-troubleshooting` | 分野7 のタスク 7.1〜7.3 |

各章の範囲の補足（タスクの原文と公式の日本語訳、対策講座の学習目標は `blueprint.md` の4章にある）:

1. **伝わるプロンプトの作り方** — 1.1 ビジネスタスクと技術タスクのための効果的なプロンプト（対象読者、目的、含めたい要点、形式、長さを伝える。繰り返し使える部品の構造）。1.2 タスク分解で複雑な依頼を構造化する。1.3 反復的に改良する（当てずっぽうではなく、何が足りなかったかを見て直す）。1.4 タスクの種類（分析、調査、下書き、ブレインストーミング）に応じて戦略を変える。根拠は Anthropic の公式のプロンプトのガイド（ヘルプセンター、Claude Docs の Prompting best practices）と AI Fluency。うまくいかないときの診断は第8章。
2. **出力を確かめる** — 2.1 出力の正確性と網羅性を評価する（正確かどうかと、抜けがないかは別々に確かめる）。2.2 ハルシネーション、不整合、バイアスを見つける（流ちょうさや自信は正しさの証拠にならない。番号や引用のような具体的に見える細部も作られうる）。2.3 ファクトチェックと検証の手法（元の資料や一次情報と照らす。Claude に自己採点させても検証にならない）。公式サンプル問題1（規制の要約の項番号を、送る前に条文と照らす）がこの範囲。
3. **人の確認と仕上げ** — 2.4 人間によるレビューや追加の検証が必要な場面の判断（誰に届くか、間違えたときの影響の大きさ）。2.5 対象者に合わせて出力を編集、調整、改良、比較する。2.6 情報を整理・選別し、適切な出力形式を選ぶ（アーティファクト、インライン、構造化データ）。
4. **製品とモデルの選び方** — 3.1 製品機能の選択（プロジェクト、リサーチ、チャット、アーティファクト。互いに組み合わせて使える）。3.2 モデルの種類（Haiku、Sonnet、Opus）の違い。3.3 タスクの要件（コスト、速度、品質）に合わせたモデル選択（公式サンプル問題2: 単純で大量の作業には速く安いモデル）。3.4 コンテキストの制限とメモリ（やり直す、要約する、保持するタイミング）。**製品の機能は変わりやすい。** ヘルプセンター（support.claude.com）で2026年11月時点の内容を確かめ、プランごとの提供状況や上限の数字は言い切らない。現行のモデルには Fable もあるが、v1.0 のガイドが挙げるのは Haiku、Sonnet、Opus の3種類（その旨を一言添える）。
5. **業務への組み込み** — 4.1 要件とユースケースの分析に Claude を使う。4.2 調査、計画、プロセスの最適化に活用する。4.3 ソリューションの設計、開発、反復的な改善を支援させる。4.4 既存のワークフローに組み込み、強化または再設計する（手順ごとに、AI に任せる、人が担う、協働する、を決める。間違った手順を自動化すると逆効果）。4.5 Claude の価値と限界をステークホルダーに正確に伝える。AI Fluency の「委任（Delegation）」が柱。
6. **設定とナレッジ管理** — 5.1 指示とナレッジソースでプロジェクトを設定する。5.2 アップロードしたナレッジとコネクタ（Google Drive、Gmail など）を管理する。5.3 効果的なシステムレベルの指示（プロジェクトの指示）を作る。5.4 設定、ナレッジソース、指示を最新に保つ（古くなった設定が不調の原因になる）。「良いプロンプトは一度だけ役に立つ。良い設定は毎回役に立つ」。機能の仕様はヘルプセンターで確かめる。
7. **ガバナンスと責任ある利用** — 6.1 適切なユースケースと不適切なユースケースの見分け。6.2 データの機密性、規制、プライバシーの考慮（公式サンプル問題3: 規制対象の個人データは、入れる前に削除または匿名化する。「保持しないで」と頼んでも管理策にはならない）。6.3 組織の AI ポリシーとガバナンス基準に従う（ベンダーの安全方針は、自社のルールの代わりにならない）。6.4 AI 利用の倫理的な影響。特定の法律の名前や条文を正解の根拠にしない。
8. **うまくいかないときの直し方** — 7.1 期待どおりに働かないプロンプトや質の低い出力の原因を特定し、直す（対策講座が挙げる4つの根本原因: 指示の不足、コンテキストの詰め込みすぎ、機能やモデルの選び間違い、設定が古い）。7.2 フィードバックと結果に基づいてやり方を変える（同じ手直しを繰り返さず、恒久的な修正に変える）。7.3 ワークフローの効率と効果を高める（共通の文脈、形式、検証の手順を、プロジェクト、Skills、常設の指示に移す）。最後の章なので、後半で講座全体を短く振り返ってよい。

## 問題集の配分（全100問）

配点にそのまま比例させる。ファイルと、使える `id` の範囲:

| 担当 | ファイル | 問題数と `id` |
|---|---|---|
| A1 | `data/d1-d7-prompting.json` | 分野1 ×14（D1-01〜14。タスク 1.1〜1.4 に各3〜4問）＋ 分野7 ×10（D7-01〜10。タスク 7.1〜7.3 に各3〜4問） |
| A2 | `data/d2-evaluation.json` | 分野2 ×21（D2-01〜21）。タスク 2.1〜2.6 に各3〜4問 |
| A3 | `data/d3-d5-product-and-config.json` | 分野3 ×12（D3-01〜12。タスク 3.1〜3.4 に各3問）＋ 分野5 ×12（D5-01〜12。タスク 5.1〜5.4 に各3問） |
| A4 | `data/d4-workflow.json` | 分野4 ×16（D4-01〜16）。タスク 4.1〜4.5 に各3〜4問 |
| A5 | `data/d6-governance.json` | 分野6 ×15（D6-01〜15）。タスク 6.1〜6.4 に各3〜4問 |

- 複数選択（`multi`）は、各担当の問題数の15%くらい。残りは択一（`single`）。`scenario` は付けない。
- `ref` には、対応するタスクを入れる（例: 「試験ガイド 分野2 タスク 2.3（ファクトチェックと検証の手法）」）。番号は便宜上のものなので、タスクの名前も添える。
- 登場人物は非エンジニア（営業、マーケティング、人事、経理、広報、カスタマーサポート、PM、教員、コンサルタントなど）。コード、API、JSON などの技術の話を出さない。
- 正解は「業務の目的を果たしつつ、確かめられ、ルールに沿った、ちょうどよい大きさの手」。誤答の定番: 流ちょうさや自信を信じる（そのまま送る、Claude に自己採点させる）、見た目だけの対処（言い換え、書式の整え直し）、極端な対処（業務をやめる、機能を全部止める、ほかの製品に替える）、本当の管理策の代わりにモデルに頼む、いつも最上位のモデルを使う、自分で作り込もうとする（技術担当に渡すべき場面で）。
