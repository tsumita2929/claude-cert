# 台本の書き方

台本（`episodes/<ep>/episode.json`）は、ナレーションと画面の両方を決める唯一のファイル。
ここでは「何をどう書くと、見て覚えられる動画になるか」を説明する。場面ごとの項目は `scenes.md` を見る。

## 目次

1. 台本の骨組み
2. 構成の型
3. ナレーションの文体
4. 表示と読みを分ける
5. step と mark：画面をナレーションに合わせる
6. 間の取り方
7. クイズの作り方
8. 書き終えたら

## 1. 台本の骨組み

```json
{
  "number": 1,
  "title": "Messages API の基本",
  "subtitle": "必須パラメータと system の渡し方",
  "thumbnail": {"headline": "必須は\n3つだけ", "sub": "Messages API の基本"},
  "scenes": [
    {
      "id": "params",
      "type": "points",
      "chapter": "必須パラメータ",
      "props": { "heading": "必須パラメータは3つ", "items": [ … ] },
      "lines": [
        {"text": "リクエストの必須パラメータは、3つです。"},
        {"text": "使うモデルを表す、`model`。", "step": 1}
      ]
    }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `number` | 第何回か。冒頭とサムネイルに出る。全何回かは `project.json` の `episodes` |
| `title` | 題名。全角20字まで。冒頭と上端の帯に出る |
| `subtitle` | 冒頭で題名の下に出す1行 |
| `thumbnail.headline` | サムネイルの大きな文字。2行まで、1行は全角6字まで（4字以下がいちばん大きい）。`\n` で改行。省略すると題名 |
| `thumbnail.sub` | サムネイル下部の補足。省略すると `subtitle` |
| `scenes[].id` | 場面の名前（英数字）。確認や修正のときに場面を指すのに使う |
| `scenes[].type` | 場面の種類。`scenes.md` の8種 |
| `scenes[].chapter` | ここから新しい章が始まることを示す見出し。YouTube のチャプターと、上端の進行表示になる |
| `scenes[].props` | 画面に出す内容。種類ごとに決まっている |
| `scenes[].lines` | ナレーション。1要素が1文で、1枚の字幕になる |

必要なときだけ、トップレベルに次も書ける（`project.json` に書けば全部の回に効く）。

| 項目 | 意味 |
|---|---|
| `voice` | この回だけ声を変える。例 `{"engine": "aivis", "speaker": 888753760}` |
| `bgm` | BGM を流す。例 `{"file": "bgm/calm.mp3", "volume": 0.05}`。ファイルは `public/` の下に置く。繰り返し再生される。音量は 0.03〜0.08（ナレーションの邪魔をしない大きさ）。収益化する動画で使える素材かを確かめる |
| `captions` | `false` で下端の字幕の帯を消す。既定は表示 |
| `lexicon` | この回だけに効く読み方辞書。`{"表記": "読み"}`。プロジェクトの `lexicon.json` に重ねて使われる。複数の回を並行して作るときは、共有の `lexicon.json` を書き換えずにここへ書く |

## 2. 構成の型

5〜8分の講義動画は、次の型に当てはめると迷わない。

| 順 | 場面 | 役割 | 長さの目安 |
|---|---|---|---|
| 1 | `title` | 何の話か、見ると何がわかるかを2〜3文で言う | 10〜15秒 |
| 2 | 本題の場面を 6〜12 個 | 1場面1メッセージ。種類は内容で選ぶ | 各 15〜40秒 |
| 3 | `quiz` | いま説明したことを1問だけ問う | 25〜35秒 |
| 4 | `summary` | 覚えて帰ることを2〜4個。次回の予告 | 15〜20秒 |

- **冒頭で結論の範囲を言う。**「今回は A と B の2点です」と先に言うと、視聴者は見通しを持って聞ける。
  あいさつや前置きは短く。最初の15秒で離脱が一番多い。
- **章（`chapter`）は 3〜7 個。** 1つの章は10秒以上にする（YouTube の決まり）。最初の場面には必ず付ける。
- **1場面に詰め込まない。** 1場面のナレーションは 3〜7 文。それより長くなるなら場面を分ける。
  同じ画面が30秒以上変わらないと、視聴者は画面を見なくなる。
- **内容で場面の種類を選ぶ。** 用語と説明の対応は `points`、数字は `stats`、対比は `compare`、順序は `flow`、
  書き方の実例は `code`。迷ったら `points`。同じ種類が3場面続いたら、どれかを別の種類で見せられないか考える。
- 長い章を複数の動画に分けるときは、各動画の最後の `summary.next` で次の動画につなぐ。

## 3. ナレーションの文体

ナレーションは読む文章ではなく、聞く文章。字幕にもなるので、短さがそのまま読みやすさになる。

- **1文は全角35字以内がいちばん読みやすい。上限は58字**（半角は0.5字と数える。超えると `check` がエラーにする）。
  字幕の1行に入るのは33字ほどで、それを超えると2行になる。2行になる文は、**中ほどの句読点の位置で折れる**。
  中ほどに句読点がないと文節の途中で折れて読みにくいので、35字以内に切るか、折れてほしい位置に読点を打つ
  （`check` が注意を出す）。長い文は「〜で、〜ので、〜ですが」の接続を切って2文にする。
- **1文に1つのことだけ。**「A は B です。そして C です。」のほうが「A は B で、C でもあります。」より聞き取りやすい。
- **です・ます体で、言い切る。**「〜と言えるでしょう」「〜かもしれません」は、事実が不確かなとき以外は使わない。
  不確かなら、何が不確かなのかを言う（「試験の形式は、第三者の情報です」）。
- **読点（、）を、息継ぎの位置に打つ。** 音声エンジンは読点で短い間を取る。用語の前に打つと、用語が聞き取りやすくなる
  （「使うモデルを表す、`model`。」）。
- **同じ用語は同じ言い方で通す。**「システムプロンプト」と「システム指示」を混ぜない。
- **画面に出ている文字を、そのまま全部は読まない。** 画面には結論を短く、ナレーションでは理由や注意を足す。
  ただし、覚えてほしい用語は画面にも出し、声でも言う。
- 記号や URL は読まない。括弧書きは使わず、文にする。
- **長い英語の名前は、声では読まない。** `content_block_stop` や `input_json_delta` のような長い名前をカタカナで読ませると、
  音声エンジンが語の途中で区切ってしまい、聞き取れない。声では役割を日本語で言い（「ブロックの終わりを知らせるイベント」）、
  名前は画面の項目に出す。短くて覚えてほしい名前（`max_tokens`、`stop_reason`、`message_delta`）は読んでよい。

悪い例と直した例:

```
× システムプロンプトについては、messages の配列の中に入れるのではなく、トップレベルに用意されている system というパラメータを使って渡すことになっています。
○ システムプロンプトは、トップレベルの `system` パラメータで渡します。
○ `messages` の配列に入れるのは、会話だけです。
```

## 4. 表示と読みを分ける

`text` は画面（字幕）に出す表記で書く。読み上げ用の文は、次の順で自動的に作られる。

1. 行に `read` があれば、それをそのまま読む。
2. なければ `text` から記法の記号を外し、`lexicon.json` の用語を読みに置き換える。

```json
{"text": "出力の上限を決める、`max_tokens`。"}
```
`lexicon.json` に `"max_tokens": "マックストークンズ"` があれば、「出力の上限を決める、マックストークンズ。」と読む。

```json
{"text": "正解は C。", "read": "正解は、シー。"}
```
1文字の英字や、文脈で読みが変わる語は `read` で指定する。

**記法**（`text` と、`props` の中の表示用の文で使える）:

- `` `max_tokens` `` … 等幅の書体にする。コード上の名前（パラメータ、関数、コマンド、値）だけに使う
- `==ここが大事==` … 蛍光ペンを引く。1場面に1か所まで
- `\n` … そこで改行する。見出しや問題文が変な位置で折れるときだけ使う（ナレーションの `text` には使わない）

**`lexicon.json`** は「表記 → 読み」の対応表。長い表記から先に置き換えるので、`Messages API` と `API` の両方を登録してよい。
大文字と小文字は区別する。読みはカタカナで書くと安定する。
英数字の表記は、**単語として現れたときだけ**置き換わる（`text` を登録しても、`context` の中の text は置き換わらない）。
数字も登録できる（`"429": "ヨンニーキュー"`）。ただし「500番台」のように別の読みにしたい形は、長い表記として別に登録する。

## 5. step と mark：画面をナレーションに合わせる

行に `step` を付けると、**その文を読み始めた瞬間に**、画面が指定した段階に進む。段階の意味は場面の種類ごとに決まっている
（`scenes.md`）。たとえば `points` では、step 2 で2番目の行まで見える。

```json
"lines": [
  {"text": "リクエストの必須パラメータは、3つです。"},
  {"text": "使うモデルを表す、`model`。", "step": 1},
  {"text": "出力の上限を決める、`max_tokens`。", "step": 2},
  {"text": "そして、会話の中身である、`messages` です。", "step": 3},
  {"text": "この3つは、必ず覚えてください。"}
]
```

- 最初の文（step なし）のあいだは、見出しと空の枠だけが見えている。「これから3つ出る」ことが先に伝わる。
- **その項目の話を始める文に step を付ける。** 説明し終わってから出すと、視聴者は何の話か分からないまま聞くことになる。
- 場面の行に step を1つも書かなければ、その場面は最初から全部を出す。短い場面ではそれでよい。
- `mark` は赤ペンの印。その文を読み始めたときに印が入る。対象の指定は種類ごとに違う（`points` なら行の番号、0始まり）。
  **1場面に1か所まで。**「試験に出るのはここ」「間違えやすいのはここ」の1点に使う。
  文の途中で印を入れたいときは `"markAt": 1.2`（文の開始からの秒数）を足す。

## 6. 間の取り方

間は自動で入る。文と文のあいだが 0.3 秒、場面の最初が 0.5 秒、最後が 0.7 秒。変えたいときだけ書く。

| 書き方 | 意味 |
|---|---|
| 行に `"pause": 0.8` | この文のあとの間を 0.8 秒にする。話題の変わり目や、大事なことを言った直後に |
| 行として `{"wait": 4}` | 無音で 4 秒待つ。クイズの考える時間など。`step` を付けられる |
| 場面に `"before": 1.0` / `"after": 1.5` | 場面の最初・最後の無音。図を見せてから話し始めたいときなど |

## 7. クイズの作り方

- **その動画で説明したことだけを問う。** 説明していない知識が必要な問題は、視聴者を置いていく。
- **問題は自作する。** 実際の試験問題や、他社の問題集の問題は使わない。ユーザー自身の問題集があれば、そこから選んで短くする。
- 選択肢は 4 つが基本。1つの選択肢は全角34字まで、1行に収める。長い選択肢は読めない。
- 誤答は「よくある間違い」から作る。明らかに変な誤答は、考える材料にならない。
- 「上記すべて」「いずれでもない」は使わない。
- 問題文はナレーションで読む。選択肢は読まなくてよい（読むと長い）。考える時間は 4〜5 秒。
- 正解の発表では、**なぜ正しいか**を1文、できれば**なぜ他が違うか**を1文足す。

```json
"lines": [
  {"text": "ここで、ミニクイズです。"},
  {"text": "（問題文）"},
  {"text": "正しい直し方は、どれでしょうか。", "step": 1},
  {"wait": 4, "step": 2},
  {"text": "正解は C。（正解の内容）です。", "read": "正解は、シー。（正解の内容の読み）です。", "step": 3},
  {"text": "（ほかの選択肢が違う理由）", "step": 4}
]
```

## 8. 書き終えたら

`check` を通す前に、台本を声に出すつもりで読み直す。

- 1文ずつ、息継ぎなしで言えるか。言えなければ切る。
- 画面の見出しだけを順に読んで、話の筋が通るか。通らなければ、場面の順序か見出しを直す。
- その場面の画面を見ずに、ナレーションだけ聞いて意味が通じるか（ながら聞きの視聴者は多い）。
- 逆に、音を消して画面と字幕だけで意味が通じるか（音を出せない視聴者も多い）。
