# 場面の種類

場面は8種類。台本の `type` に名前を書き、`props` に画面の内容を、`lines` にナレーションを書く。
すべての種類を使った実例が、このスキルの `assets/template/episodes/example/episode.json` にある
（`init` した直後の動画プロジェクトなら `episodes/example/` にも入っている）。

## 目次

- 選び方
- 共通の決まり（文字数、step のない場面）
- `title` / `points` / `stats` / `code` / `compare` / `flow` / `quiz` / `summary`
- 場面の種類を足すとき

## 選び方

| 伝えたいこと | 種類 |
|---|---|
| 動画の題名と、何がわかるか | `title` |
| 用語と説明の組（パラメータ、状態、条件の一覧） | `points` |
| 覚える数字（問題数、時間、上限値、割合） | `stats` |
| 書き方の実例（リクエスト、設定、コマンド） | `code` |
| 2つの対比（する／しない、A方式／B方式） | `compare` |
| 順番に進むもの（処理の流れ、イベントの順序） | `flow` |
| 理解の確認 | `quiz` |
| 覚えて帰ること、次回の予告 | `summary` |

## 共通の決まり

**文字数。** 全角を1字、半角を0.5字と数える。上限を超えると `check` がエラーにする。
上限は「画面に収まる最大」であって目標ではない。短いほど大きく表示され、読みやすくなる
（`points`・`compare`・`code`・`quiz`・`flow` は、内容が少ないほど自動で大きく組む）。

| 項目 | 上限 |
|---|---|
| `heading`（見出し） | 24字。1行に収める |
| `lead`（見出しの下の補足） | 44字。なくてもよい。入れると本文に使える高さが1行ぶん減る |
| ナレーションの1文（字幕） | 58字 |

**`heading` は結論を書く。**「エラー処理について」ではなく「再試行するエラー、直すエラー」。

**step のない場面。** `lines` に `step` を1つも書かないと、その場面の内容は最初から順に全部出る。

**章名（`chapter`）は短く。** 全角6字前後が目安。題名と合わせて長いと、上端の帯に入りきらず「…」で省略される（`check` が注意を出す）。

**記法。** `props` の表示用の文（見出し、説明、選択肢、コードの注釈など）では、`` `コード` `` と `==強調==` が使える。
`\n` を入れると、そこで改行する（見出しや問題文が変な位置で折れるときに使う）。
バッククォートで囲んだ語は等幅になり、前後に余白も付くので、文字数の見積もりより少し幅を取る。多用した文は短めに書く。

## title

動画の冒頭。`props` は不要。台本のトップレベルの `title`・`subtitle`・`number` と、`project.json` の
`series`・`disclaimer`・`episodes` が出る。右側の解答用紙が鉛筆で塗られていく。

```json
{"id": "open", "type": "title", "chapter": "オープニング",
 "lines": [
   {"text": "CCDV-F キャッチアップ講座、第1回です。"},
   {"text": "今回は、すべての土台になる Messages API の基本を押さえます。"}
 ]}
```

- `title` は全角20字まで。8字以下だと大きく、長いほど小さくなる。8字を超えると2行に折れることがある
  （折れる位置は文節の切れ目で、自動で決まる）。
- 最初の場面なので `chapter` を必ず付ける。

## points

用語と説明の表。いちばん出番が多い。

| props | 意味 |
|---|---|
| `heading`, `lead` | 見出しと補足 |
| `items` | 2〜5個。各 `{label, desc, mono}` |
| `items[].label` | 用語。短く |
| `items[].desc` | 説明。2行まで（3行以上はエラー） |
| `items[].mono` | `true` で用語を等幅に（コード上の名前のとき） |
| `ordered` | `true` で楕円に番号を入れる。順位や手順のときだけ |

- **step k** … k 番目の行までが出る（楕円が鉛筆で塗られ、用語と説明が現れる）。
- **mark** … 行の番号（0始まり）。その行の用語に赤ペンの下線。

```json
{"id": "params", "type": "points", "chapter": "必須パラメータ",
 "props": {
   "heading": "必須パラメータは3つ",
   "lead": "どれか1つでも欠けると、リクエストは受け付けられない",
   "items": [
     {"label": "model", "mono": true, "desc": "使うモデルの ID"},
     {"label": "max_tokens", "mono": true, "desc": "1回の応答で生成する出力の上限"},
     {"label": "messages", "mono": true, "desc": "`user` と `assistant` が並ぶ、会話の中身"}
   ]},
 "lines": [
   {"text": "リクエストの必須パラメータは、3つです。"},
   {"text": "使うモデルを表す、`model`。", "step": 1},
   {"text": "出力の上限を決める、`max_tokens`。", "step": 2},
   {"text": "そして、会話の中身である、`messages` です。", "step": 3, "mark": 1}
 ]}
```

- 3個以下で説明が1行なら、大きく組まれる。2個で説明が1行なら、さらに大きくなる。5個で説明が2行のものが多いと収まらない。その場合は2場面に分ける。
- 2個だけの一覧は、大きく組んでも画面の下が空きやすい。3個にできないか、`compare` や `stats` で見せられないかを考える。
- **説明は1行に収めると読みやすい。** 1行に入るのは全角22〜28字ほど（用語が長いほど短くなる）。
  最後の数文字だけが2行目に落ちる場合は、`check` が注意を出すので削る。

## stats

覚える数字を、答案用紙の記入欄の形で見せる。

| props | 意味 |
|---|---|
| `heading`, `lead` | 見出しと補足 |
| `items` | 2〜4個。各 `{value, unit, label, note}` |
| `items[].value` | 数字。4桁まで |
| `items[].unit` | 単位（問、分、点、%）。短く |
| `items[].label` | 欄の名前（問題数、試験時間）。10字まで |
| `items[].note` | 補足。2行まで |

- **step k** … k 番目の欄までに数字が入る。
- **mark** … 欄の番号（0始まり）。数字に赤ペンの下線。

```json
{"id": "format", "type": "stats",
 "props": {
   "heading": "試験の形式",
   "items": [
     {"value": 53, "unit": "問", "label": "問題数", "note": "択一と複数選択"},
     {"value": 120, "unit": "分", "label": "試験時間", "note": "1問あたり2分強"},
     {"value": 720, "unit": "点", "label": "合格ライン", "note": "1000点満点"}
   ]},
 "lines": [
   {"text": "問題数は、53問。", "step": 1},
   {"text": "試験時間は、120分です。", "step": 2},
   {"text": "合格ラインは、720点と言われています。", "step": 3, "mark": 2}
 ]}
```

- 数字の出典が公式でないときは、`note` かナレーションでそう言う。

## code

コードや設定の実例。暗い背景に等幅で出す。

| props | 意味 |
|---|---|
| `heading`, `lead` | 見出しと補足 |
| `lang` | 色分けの言語。`json` `python` `tsx` `yaml` `go` `markdown` など。対応しない言語は色分けなしで出る |
| `code` | コード。**11行まで**。改行は `\n` |
| `focus` | 注目する行。`focus[k-1]` が step k のときに明るくする行番号（1始まり）の配列 |
| `notes` | 注釈。`notes[k-1]` が step k のときに、注目行の右に出る付箋。不要な段階は `null` |

- **step k** … `focus[k-1]` の行だけ明るくし、ほかを暗くする。`notes[k-1]` があれば付箋を出す。
- mark はない（注目行の表示が印の役割をする）。

```json
{"id": "system", "type": "code",
 "props": {
   "heading": "`system` はトップレベルで渡す",
   "lang": "json",
   "code": "{\n  \"model\": \"claude-sonnet-5-5\",\n  \"max_tokens\": 1024,\n  \"system\": \"あなたは丁寧なサポート担当です。\",\n  \"messages\": [\n    {\"role\": \"user\", \"content\": \"返品方法を教えて\"}\n  ]\n}",
   "focus": [[4], [5, 6, 7]],
   "notes": ["システムプロンプトはここ", "ここは会話だけ"]},
 "lines": [
   {"text": "システムプロンプトの渡し方にも、決まりがあります。"},
   {"text": "システムプロンプトは、トップレベルの `system` パラメータで渡します。", "step": 1},
   {"text": "`messages` の配列に入れるのは、会話だけです。", "step": 2}
 ]}
```

- **説明に必要な行だけ残す。** 実際のコードをそのまま貼ると読めない。6行以下がいちばん大きく読みやすい。
- コードの中身（モデル名、パラメータ名、値）も事実確認の対象。動かないコードを見せない。
- 注釈は短く（付箋が注目行のコードと重なると `check` がエラーにする）。

## compare

2つを左右に並べる。

| props | 意味 |
|---|---|
| `heading`, `lead` | 見出しと補足 |
| `left`, `right` | 各 `{title, items, tone}` |
| `title` | 列の見出し。16字まで |
| `items` | 1〜4個。各 `{label, desc, mono}`。`label` は18字まで、`desc` は2行まで |
| `tone` | `"ng"` で列を赤にする。「してはいけない側」のときだけ |

- **step 1** … 左の中身が出る。**step 2** … 右の中身が出る。枠と列の見出しは最初から見えている。

```json
{"id": "retry", "type": "compare",
 "props": {
   "heading": "再試行するエラー、直すエラー",
   "left": {"title": "再試行する", "items": [
     {"label": "429", "mono": true, "desc": "レート制限"},
     {"label": "529", "mono": true, "desc": "過負荷"}]},
   "right": {"title": "直す", "tone": "ng", "items": [
     {"label": "400", "mono": true, "desc": "リクエストの誤り"},
     {"label": "401", "mono": true, "desc": "認証エラー"}]}},
 "lines": [
   {"text": "時間をおけば直るエラーは、再試行します。", "step": 1},
   {"text": "リクエストが間違っているエラーは、何度送っても失敗します。直すしかありません。", "step": 2}
 ]}
```

- 左右の項目数はそろえる。片方だけ多いと、対比に見えない。
- **各列2項目までで、どの行も1行に収まる（説明は全角およそ20字以内）と、大きく組まれる。**
  1字でも超えると小さい組みになり、画面の下が大きく空く。`check` が注意を出すので、説明を削る。
- 各列1項目だけだと枠が小さく、画面が寂しくなる。2項目ずつが収まりがよい。

## flow

順番に進むものを、左から右へ箱と矢印で並べる。

| props | 意味 |
|---|---|
| `heading`, `lead` | 見出しと補足 |
| `nodes` | 3〜5個。各 `{label, desc, mono}` |
| `nodes[].label` | 箱の中の語。3個なら10字、4〜5個なら9字まで |
| `nodes[].desc` | 箱の下の説明。3個なら42字、4個なら34字、5個なら30字まで |

- **step k** … k 番目の箱までが出て、k 番目の箱が塗られる（いま話している箱）。

```json
{"id": "exchange", "type": "flow",
 "props": {
   "heading": "やり取りの流れ",
   "nodes": [
     {"label": "リクエスト", "desc": "ブラウザが URL を指定して送る"},
     {"label": "処理", "desc": "サーバーが内容を調べる"},
     {"label": "レスポンス", "desc": "先頭にステータスコードが付く"}]},
 "lines": [
   {"text": "ブラウザが、リクエストを送ります。", "step": 1},
   {"text": "サーバーが、それを処理します。", "step": 2},
   {"text": "そして、ステータスコードを付けたレスポンスを返します。", "step": 3}
 ]}
```

- 順序に意味がないものには使わない（`points` を使う）。
- **箱は4個まで**がよい。5個並べると文字がかなり小さくなる（`check` が注意を出す）。
- 箱の下の説明は幅が狭く、最後の2〜3字だけが次の行に落ちやすい。`check` が注意を出したら、削るか `\n` で折る位置を指定する。
- 箱の語が長い（`content_block_delta` など）、または6個以上あるときは、`points` に `"ordered": true` を付けて縦に並べる。

## quiz

ミニクイズ。選択肢はマークシートの形で、正解は鉛筆で塗って赤ペンの丸を付ける。この動画の見せ場。

| props | 意味 |
|---|---|
| `question` | 問題文。62字まで（2行）。`\n` で折り返し位置を指定できる |
| `options` | 選択肢。2〜5個、各34字まで（1行） |
| `answer` | 正解の番号（0始まり）。複数正解なら配列 |
| `explain` | 解説。40字まで（1行） |
| `label` | 左上の札の文字。省略すると「ミニクイズ」 |

step の意味は決まっている。

| step | 画面 |
|---|---|
| なし | 問題文だけ |
| 1 | 選択肢が出る |
| 2 | 考える時間。`{"wait": 4, "step": 2}` と書く。1秒ごとに楕円が塗られる |
| 3 | 正解を鉛筆で塗り、赤ペンの丸を付ける。ほかの選択肢は薄くなる |
| 4 | 解説が出る。step 4 の行がなければ、step 3 と同時に出る |

記入例は `script-guide.md` の「クイズの作り方」と、見本の台本（`assets/template/episodes/example/episode.json`）を見る。

- `heading` はない。問題文が見出しの役割をする。
- 正解を読み上げる行は、「正解は C。」のように記号を言う。1文字の英字は読みが不安定なので `read` を付ける。

## summary

最後のまとめ。項目ごとに赤ペンのチェックが入る。

| props | 意味 |
|---|---|
| `heading` | 省略すると「今回のまとめ」 |
| `items` | 2〜4個の文。各27字まで |
| `next` | 次回の予告。30字まで。なくてもよい |

- **step k** … k 番目の項目にチェックが入る。**step（項目数+1）** … 次回の予告が出る。

```json
{"id": "wrap", "type": "summary", "chapter": "まとめ",
 "props": {
   "items": ["必須は `model`・`max_tokens`・`messages`", "`system` はトップレベルで渡す"],
   "next": "`stop_reason` の読み方"},
 "lines": [
   {"text": "今回のまとめです。"},
   {"text": "必須パラメータは、`model`、`max_tokens`、`messages` の3つ。", "step": 1},
   {"text": "システムプロンプトは、トップレベルの `system` で渡す。", "step": 2},
   {"text": "次回は、`stop_reason` の読み方を見ていきます。", "step": 3}
 ]}
```

- 項目は、本題の場面の見出しとほぼ同じ言葉にする。新しい情報をここで足さない。

## 場面の種類を足すとき

既存の8種で表せない内容（グラフ、図解、画面の録画など）が繰り返し出てくるなら、種類を足す。1回きりなら既存の種類で工夫する。

1. `src/scenes/<名前>.tsx` に部品を書く。`useSteps()` で段階を、`useMark()` で赤ペンの印を受け取る
   （`src/timing.tsx`）。色と書体は `src/theme.ts` から取る。既存の部品（`Points.tsx` が素直）を手本にする。
2. `src/Frame.tsx` の `SCENES` に登録する。
3. `scripts/certvideo.py` の `check_scene_props` に、必須の項目と文字数の検査を足す。
   検査がないと、はみ出す台本がそのまま書き出されてしまう。
4. このファイルに、使いどころ・項目・step の意味・記入例を足す。
5. その種類を使った短い台本を書き出し、`qa` のコマ画像で確かめる。
