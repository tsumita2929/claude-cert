# 資格の解説動画を作る

教材（台本、スライド、問題集など）から、ナレーションと画面がそろった解説動画を作る。
動画は「台本ファイル（episode.json）」から機械的に書き出すので、**品質は台本で決まる**。
このスキルの仕事の大半は、良い台本を書くことと、書き出した結果を自分の目で確かめることにある。

```
素材を読む → 構成と台本 → 事実確認 → 検査 → 音声 → 読みの確認 → 画面の下見 → 書き出し → 画面と音量の確認 → 公開用の文面
            episode.json   factcheck.md  check   voice   readings.md    preview     render      qa               youtube.md
```

コマンドはすべて `scripts/certvideo.py`（このスキルのフォルダにある。標準ライブラリだけで動く）。
以下では `cv` と書く。`<project>` は動画プロジェクトのフォルダ（ふつうは `video`）、`<ep>` は回の名前。

```bash
cv() { python3 <このスキルのフォルダ>/scripts/certvideo.py "$@"; }
```

（変数に入れて `$CV check …` と呼ぶ書き方は、zsh では動かない。シェル関数にするか、毎回 `python3 …/certvideo.py` と書く。）

## 最初の1回：プロジェクトを用意する

`<project>/package.json` がすでにあれば、この節は飛ばす。

1. **作る。** `cv init video` でテンプレートを複製し、パッケージを入れる（1〜2分）。
2. **見本で動作を確かめる。** `cv voice video example && cv render video example` が通れば環境は整っている。
   音声エンジンは Docker で自動起動する。詳しくは `references/voices.md`。
3. **シリーズの設定を書く。** `video/project.json` の `series`（シリーズ名）、`disclaimer`（冒頭に出す断り書き）、
   `episodes`（全何回か）、`exam`（資格の略称 `short` と正式名 `full`。題名や概要欄に使う）を、ユーザーの題材に合わせる。
   資格の正式名は推測で書かず、ユーザーに確認するか公式の表記を調べる。
4. **声をユーザーに選んでもらう。** 声は好みが分かれ、文字では判断できないので、必ず聴いてもらう。
   `cv audition` で同じ文を複数の声で読ませ、できた `out/_audition/index.html` を開いて番号で選んでもらう。
   収益化する動画では、候補に入れる前に各声の利用規約を確かめる（`references/voices.md`）。
   決まったら `project.json` の `voice` と `credit` に書く。
5. **用語の読み方辞書を作る。** 題材の頻出用語（英字の略語、製品名、コード上の名前）を `video/lexicon.json` に入れる。

見本の回（`episodes/example`）は、8種類の場面をすべて使った台本の実例として残しておく。

## 1本作る

### 1. 素材を読み、1本の範囲を決める

- **1本は1テーマ、5〜8分**（ナレーション 1,800〜2,800 字。話す速さは声で変わるが、およそ毎分350字）。長い章は分ける。視聴者は「このテーマを知りたい」で動画を選ぶので、
  1本に詰め込むより、題名で中身が言い切れる単位に割るほうが見られる。
- 既存の教材があるなら、その章立てと用語に合わせる。動画だけ言い回しが違うと、教材を併用する人が混乱する。
- 事実確認つきの講座の本文（`course/chNN.md` のような、章ごとの本文と「事実確認」の表）がある場合は、それを素材にする。
  地の文がナレーションの元、「要点」が画面の項目の元、「事実確認」の表が `factcheck.md` の元になる。素材にない事実を足さない。
  動画を作る途中で素材の誤りに気づいたら、動画だけ直して終わりにせず、素材（と、同じ素材から作った音声・スライド）にも戻す。
- 2分前後の短い回を頼まれたら、冒頭・クイズ・まとめだけで約1分かかる。本題は2〜3場面に絞る。
- 素材が古い・出典が不明な場合は、この段階でユーザーに伝える（事実確認の対象が増える）。

### 2. 台本を書く

`video/episodes/<ep>/episode.json` を書く。書き方は **`references/script-guide.md`**、場面の種類と項目は **`references/scenes.md`** を読む。
要点だけ挙げる。

- **1場面1メッセージ。** 見出しは、その場面で覚えてほしい結論を書く（「stop_reason について」ではなく「stop_reason を先に確認する」）。
- **1文は短く。** 1文が1枚の字幕になる。耳で聞く文章なので、主語と述語を近づけ、1文に1つのことだけを言う。
- **画面はナレーションに合わせて変える。** 行に `step` を付けると、その文を読み始めた瞬間に画面が次の段階へ進む。
  読んでいる内容と見えているものが一致していることが、スライドの読み上げとの一番の違いになる。
- **表示用の文と読みを分ける。** 画面には `max_tokens`、読み上げには「マックストークンズ」。読みは `lexicon.json` か行の `read` で指定する。
- **毎回ミニクイズを入れる。** 見るだけの動画より、一度考えさせたほうが記憶に残る。クイズは自作する。
  実際の試験問題の転載は、著作権と受験時の守秘義務に触れるので行わない。

### 3. 事実確認をする

資格の解説は、**1か所の誤りで動画全体の信用を失う**。台本の主張を一つずつ、一次情報（公式ドキュメント、試験ガイド、規格書）と照合し、
`video/episodes/<ep>/factcheck.md` に「主張・判定・根拠・確認日」の表で残す。

- 数値、名前（パラメータ名、コマンド名、条文番号）、「必ず」「〜だけ」のような言い切りは、特に確かめる。
- 一次情報で確認できない主張（第三者サイト由来の試験形式、出題傾向など）は、**削るか、出典が第三者であることを台本で明示する**。
- 素材の教材に書いてあることも確認の対象にする。教材が作られた後に仕様が変わっていることがある。
- 確認できなかった点は、黙って残さずユーザーに報告する。

### 4. 検査して、台本をユーザーに見せる

```bash
cv check video <ep>
```

文字数や行数が画面に収まるかを調べる。エラーは台本を直して消す（上限を緩めても、画面からはみ出すだけ）。
「注意」は見た目が崩れる前触れ（説明の最後の数文字だけが次の行に落ちる、字幕が文節の途中で折れる、章名が長い、など）。
書き出してから気づくと全工程のやり直しになるので、ここで直す。長さの見積もりも出るので、目標の長さに合わせて削る。

**新しいシリーズの最初の回と、ユーザーが内容を気にしている回は、音声を作る前に構成と台本を見せて合意を取る。**
台本の段階の修正は数秒で済むが、書き出した後の修正は全工程のやり直しになるからだ。
場面の一覧（種類・見出し・ナレーションの要約）を短く示し、事実確認で引っかかった点があれば一緒に伝える。
同じシリーズの2本目以降で「続きを作って」と頼まれた場合は、そのまま進めてよい。

### 5. 音声を作り、読みを確認する

```bash
cv readings video <ep>    # 先に、全文の読みだけを出す（音声は作らない。数十秒）
cv voice video <ep>       # 音声を合成する
```

**先に `readings` で読みを下見して、誤読を直してから `voice` を実行する。** 音声の合成は時間がかかるので、
合成してから誤読に気づくと、やり直しになる。

`voice` は1文ずつ合成し、長さを測ってタイムラインを作る。同じ文は作り直さないので、台本を直して再実行しても速い。
`readings` と `voice` は、どちらも **`video/out/<ep>/readings.md`** に読みの一覧を書く。**必ず読む。** 音声エンジンが実際にどう読むかがカタカナで並んでいる。

- 誤読を探す（例：「行った」が「いった／おこなった」、「方」が「かた／ほう」、英字の略語、数字と単位）。
- 1つの語の途中に「/」（アクセントの区切り）が入っていないかを見る。入っていたら不自然に聞こえる。直し方は `references/voices.md`。
- 「辞書にない英字」の列に語があれば、エンジン任せの読みになっている。`lexicon.json` に読みを足す。
- その行だけ直したいときは、行に `"read": "…"` を書く。直したら `voice` をもう一度実行する。
- 直し方を試すときは `cv reading video "試す文"`。音声を作らずに、その文の読みだけがすぐ出る。

音は聞けなくても、この表で誤読の大半は見つけられる。アクセントの違和感は表ではわからないので、最後にユーザーに聞いてもらう。

### 6. 画面を下見して直し、書き出して仕上げる

```bash
cv preview video <ep>    # 動画を書き出さずに、確認用のコマ画像とサムネイルだけを作る（10〜30秒）
cv render video <ep>     # 動画（mp4）とサムネイル（png）
cv qa video <ep>         # コマ画像の一覧と音量の測定
```

**先に `preview` で見た目を直しきってから、`render` は1回で済ませる。** 動画の書き出しは数分かかり、同じプロジェクトでは1本ずつ順番待ちになる。
`preview` は、`qa` と同じコマ（場面ごとに、各ステップが出そろった瞬間と最後のコマ）を、動画を書き出さずに画像にする
（`out/<ep>/preview/sheetNN.jpg` と `thumbnail.png`）。台本を直したら `voice` → `preview` を繰り返す。直した場面だけ見るなら `cv preview video <ep> --scene <場面のid>`。

`preview` の一覧の画像を **すべて Read で開いて見る**。検査を通っても、見た目の問題は画像でしかわからない。

- 文字のはみ出し、重なり、不自然な位置での改行（字幕を含む）
- 余白の偏り（上に寄って下が空いている、など）。項目を足すか、場面の種類を変える
- ナレーションと画面の対応（その文を読んでいるときに、該当の項目が出ているか）
- 赤ペンの印が、いちばん大事な1か所に付いているか
- サムネイル（`thumbnail.png`）が、縮小しても読めるか
- 音量が -14 LUFS ±1 に入っているか（`qa` が判定を出す）

問題があれば台本か部品を直し、該当の工程からやり直す（下の表）。

見た目の問題がなくなったら `render` で書き出し、`qa` で仕上げの確認をする。`qa` は、書き出した動画そのものからコマを抜き出し
（`out/<ep>/qa/sheetNN.jpg`）、音量を測る。`preview` で見た画面と同じはずなので、ここでは一覧をざっと見て、音量の判定と、
動画の長さ・サムネイルを確かめればよい。直した場面だけ見るなら `cv qa video <ep> --scene <場面のid>`（`qa/partial/` に出る。全体のコマ画像は消えない）。

### 7. 公開用の文面を作る

YouTube に公開する動画では、`video/episodes/<ep>/youtube.md` に題名の案、概要欄、チャプター、タグをまとめる
（手で書くファイルなので、作り直せる `out/` ではなく台本と同じ場所に置く）。
書き方と、クレジット・断り書き・公開前の確認項目は **`references/publish.md`**。
`out/<ep>/chapters.txt`（チャプター）と `captions.srt`（字幕ファイル）は `voice` が作っている。

### 8. ユーザーに渡す

できたファイルの場所（mp4、サムネイル、youtube.md）と、次のことを短く伝える。

- 事実確認で削った・言い換えた点、確認しきれなかった点
- 聞いて確かめてほしい箇所（読みを直した用語、アクセントが怪しい固有名詞）
- 動画は自分では視聴していないこと（コマ画像と読みの表で確認した範囲を正直に言う）

## 直すときに、どこからやり直すか

| 直したもの | やり直す工程 |
|---|---|
| ナレーションの文、`read`、`lexicon.json`、声 | `voice` → `preview`（見た目も変わったとき）→ `render` → `qa` |
| 画面の項目だけ（`props`）、`step` や `mark` の位置 | `voice`（音声は再利用されるので数秒）→ `preview` → `render` → `qa` |
| 題名、副題、`chapter`、サムネイルの文字（`thumbnail`）、`project.json` | 同上。これらも `voice` がタイムラインに書き込むので、`render` だけでは反映されない |
| 見た目の部品（`src/`）、色や書体（`src/theme.ts`） | `preview` → `render` → `qa` |
| 一部の場面だけ確かめたい | `cv render video <ep> --frames 300-900` で一部だけ書き出す（`<ep>.part.mp4` に出る。完成した動画は上書きしない） |

## 複数の回を並行して作るとき

サブエージェントに1本ずつ任せて、同時に作れる。台本と事実確認は並行で進み、機械の負荷が高い工程だけが順番待ちになる。

- **共有の `lexicon.json` は書き換えない。** 同時に書くと壊れる。新しい用語の読みは、各回の台本のトップレベルの `lexicon` に書く。
  読みを試すときは `cv reading video --episode <ep> "文"`。全部終わってから、共通で使う用語だけ `lexicon.json` に移す。
- **`voice` と `render` は、待ち時間の上限に縛られない形で実行する。** ほかの回と同時だと10分を超えることがある。方法は2つ。
  - Bash の `run_in_background: true` で実行し、完了の通知を待つ。
  - 通知を受け取れない場面（ワークフローのサブエージェントなど）では、`--detach` を付けて切り離し、`wait` で待つ:
    `cv voice video <ep> --detach` → `cv wait video <ep> voice`（`render` も同じ）。`wait` は最長9分待ち、まだ終わっていなければ
    終了コード 3 で戻るので、もう一度 `wait` を実行する。ログは `out/<ep>/voice.log`・`render.log` に残る。
- **書き出しは、このマシン全体で同時に2本まで。** 動画プロジェクトが複数あっても共通で数える（1本の書き出しが CPU の半分ほどを使うため）。
  枠が空くまでは「待っています」と出るので、そのまま待つ。途中で止まっても、もう一度実行すれば進む。
- **見た目の直しは `preview` で済ませ、`render` は最後に1回だけにする。** 書き出しの順番待ちが、全体でいちばん時間のかかるところになる。
  `preview` は順番待ちをしないので、ほかの回の書き出し中でも実行できる。
- **音声エンジンは止めない。** 最後に全部終わってから `engine stop` する。
- **回の題名と、前の回の「次回」の予告を先に決めて渡す。** 別々に作ると食い違う。
- 各担当が触るのは、自分の回の `episodes/<ep>/` と、コマンドが作る `out/<ep>/`・`public/ep/<ep>/` だけにする。

## 見た目の決まり

テンプレートの見た目は「答案用紙」を題材にしている。印刷インクの青緑で枠と罫線、鉛筆の黒で塗った楕円、採点の赤ペン、蛍光ペンの黄。
崩さないために、次の3点を守る。

- **赤ペンは1場面に1か所まで。** 全部に印を付けると、どれも目立たなくなる。`mark` は「これだけは覚えて」の1点に使う。
- **動きは意味のあるものだけ。** 画面が変わるのは、ナレーションがその話に入ったときだけ。飾りの動きは足さない。
- **等幅の書体は、コード上の名前だけに使う。** バッククォートで囲んだ語（`max_tokens`）が等幅になる。ふつうの英単語は囲まない。

シリーズごとに色を変えるなら `src/theme.ts` を直す。場面の種類を足す手順は `references/scenes.md` の最後にある。

## ファイルの場所

```
video/                         動画プロジェクト（init で作る）
  project.json                 シリーズ名、断り書き、声、クレジット
  lexicon.json                 用語の読み方辞書
  episodes/<ep>/episode.json   台本（これが正）
  episodes/<ep>/factcheck.md   事実確認の記録
  episodes/<ep>/youtube.md     公開用の文面（題名の案、概要欄、タグ）
  src/                         画面の部品（Remotion）。theme.ts が色と書体
  public/ep/<ep>/              voice が作るナレーション音声とタイムライン
  out/<ep>/                    完成品：<ep>.mp4、thumbnail.png、captions.srt、chapters.txt、
                               readings.md、preview/、qa/（消しても作り直せる）
  out/_audition/               声の聴き比べページ
```

## 参照資料

- `references/script-guide.md` — 台本の書き方。構成の型、ナレーションの文体、`step` と `mark`、クイズの作り方。**台本を書く前に読む。**
- `references/scenes.md` — 場面の種類（8種）ごとの使いどころ、項目、文字数の目安、記入例。**台本を書くときに開いておく。**
- `references/voices.md` — 音声エンジンの起動、聴き比べ、利用規約の確かめ方、声の調整、エンジンの追加。**声を選ぶ・変えるときに読む。**
- `references/publish.md` — YouTube の題名・概要欄・クレジット・断り書き・公開前の確認。**公開用の文面を作るときに読む。**
